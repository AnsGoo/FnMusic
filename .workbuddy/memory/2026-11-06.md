## 漫游（rom）适配 Music Free

**原状态**：`MusicFreeApi` 继承 `UnsupportedMusicApi`，`roamStart/roamNext/roamPrevious` 全返回空 `RoamDto()`。`RoamQueue` 只用 `current`/`next`，两者都 null 时 items 为空 → 点首页「漫游」卡片只弹「暂时没有可漫游的歌曲」。文档 `docs/development.md` 也把 roaming 列在「fnOS-only capabilities」里。

**实现**：Music Free 没有漫游接口，用 `GET /rest/getRandomSongs.view?size=8` 合成窗口（`MusicFreeApi.roamWindow()`）。
- 每个 `RoamItem` 的 `roamId` 必须唯一（`mf-<guid>-<自增序号>`）。若用 `mf-<guid>`，`extendRoamFrom` 里的 `requestedRoamIds.add(anchor.roamId)` 会返回 false 直接短路，队列不再增长。
- `rememberRoamTracks()` 维护 32 条 `LinkedHashSet` 最近记录做去重；库小于 32 首时回退原始响应（重复一首好过漫游中断）。
- `roamPrevious` 保持返回空：往回走由 Media3 队列自己负责，客户端从未调用 `previousRoam`（只有接口定义）。
- 单测 2 例（窗口合成 + 唯一 id、空库返回 null），`MusicFreeMappingTest` 共 17 例。

**实测（模拟器 p0 + 真实后端）**：点漫游 → 底部播放条出现《最后我们没在一起 / 白小白》；连点 3 次下一首歌名持续变化（→《Wait Wait Wait / 蔡徐坤》）；后端日志确认 `22:03:59` 起 `getRandomSongs?size=8` 每次续取一次，共 6 次。

**重要环境问题（非漫游 bug）**：DB 9557 首里 **9504 首**的 `file_path` 仍是旧 NAS 路径（`/admin 共享给我/音乐/...`），本机 `backend/music/` 只有 55 个文件。因此 `/rest/stream` 返回 `code=70 Media file not found`（HTTP 200 + XML），Media3 抛 `UnrecognizedInputFormatException: None of the available extractors could read the stream`。验证过路径有效的歌（`孤单坠爱.wma`）`curl /rest/stream` 正常返回 `200 audio/x-ms-wma 12MB`。所以漫游/播放链路本身没问题，是本地曲库数据没对齐。

## 播放容错：坏源自动跳过

**问题**：漫游窗口是随机的，一个坏文件就让整个 session 停在 `PlaybackState.ERROR`（`Source error`）。

**实现**（`core/player/.../Media3PlayerController.kt`）：
- `onPlayerError` 里先判 `isUnreadableSource()`：`ERROR_CODE_IO_FILE_NOT_FOUND / IO_BAD_HTTP_STATUS / IO_INVALID_HTTP_CONTENT_TYPE / IO_UNSPECIFIED / PARSING_CONTAINER_MALFORMED / PARSING_CONTAINER_UNSUPPORTED / PARSING_MANIFEST_* / DECODING_FORMAT_UNSUPPORTED / DECODER_INIT_FAILED` → `seekToNextMediaItem() + prepare() + play()`，不弹错误。
- **网络类错误（`IO_NETWORK_CONNECTION_FAILED/TIMEOUT`）故意不跳**：断网不能说明下一首有问题。
- `MAX_UNPLAYABLE_SKIPS = 20` 连续上限；`onEvents` 里 `player.isPlaying == true` 时清零。上限最初设 5，实测「叶惠美」前 11 首全是坏文件，5 次就停，改 20。
- 跳过时 `currentIndex` 变化会驱动 `MainViewModel.extendRoamFrom` 续取，漫游队列自动补歌。

**验证**（模拟器，真实后端）：点漫游 → `Media3Player` 日志连续 `skipping unreadable source code=3003` index 0→10，第二轮 0→8，第 20 次输出 `unplayable sources exceeded 20, surfacing the error` 后停止，不再无限跳。

**曲库扫描不是破坏性的**：`scanner.Scan()` 只 `filepath.Walk` 现存文件做新增/更新，**不会删除**数据库里缺失的记录。已触发 `/rest/startScan`，库仍是 9557 首（53 首本机文件原本就在库里）。扫描前备份：`backend/data/music.db.bak-20261106-2211`（125MB）。

**本机曲库现状**：9557 首里 9504 首 `file_path` 指向 `/admin 共享给我/音乐/...`（NAS 路径，本机不存在），可播 53 首（mp3 43 / wma 6 / m4a 3 / flac 1）。`~/Music` 只有 6 个音频文件。本地漫游必然抽到坏歌 → 连跳 20 次后报错，属数据缺失而非代码问题。要完整体验需挂载 NAS 或改 `config.yaml` 的 `music.library_path`。

## 纠正：所谓「坏曲」是沙箱代理导致的，音乐文件全部完好

**推翻前一条结论**。前面用 `os.path.exists()` 判断「9504 首文件缺失」是错的——那些歌属于 **WebDAV 媒体源**（`source_id=c3b950ef-...`，url `http://192.168.124.18:5005/`，root `/admin 共享给我/音乐/`，账号 music），路径本来就不该在本地存在。`backend/music` 那 53 首只是 `default-library` 本地源。

**真实根因**：环境变量 `HTTP_PROXY=http://127.0.0.1:61618`（WorkBuddy 沙箱代理）。Go 的 `http.ProxyFromEnvironment` 会把发往 `192.168.124.18:5005` 的内网请求也交给这个代理，代理返回 404，于是 gowebdav 报 `ReadStream ...: 404` → `serveRawFromSource` 返回 `code=70 Media file not found` → Media3 收到 XML 当音频解析 → `UnrecognizedInputFormatException`。

**证据链**：
- `curl -u music:admin@123` 拉文件 = 200，8507050 字节，`audio/x-ms-wma`（Microsoft ASF）
- 同类 gowebdav 调用在 `go test` 里（同样有代理变量）成功，在服务进程里 404 —— 差异在进程环境
- 覆盖 `HTTP_PROXY= HTTPS_PROXY= NO_PROXY='*'` 重启后，`/rest/stream` 立刻返回 `200 size=8507050`，随机 3 首分别 16MB/4MB/20MB 全部 200
- 模拟器漫游：`state=PLAYING(3) position=11080 error=null`，《搁浅 / 周杰伦》，点下一首切到《乱世浮生 / 五月天》继续播放

**文件名细节**：WebDAV 上部分文件名用的是 NBSP（U+00A0，`\xa0`）而非普通空格，DB 里存的一致（51 条含 NBSP），不是问题；日志里 `%q` 才能看出来。

**当前后端启动方式**（仅本机调试需要）：`HTTP_PROXY= HTTPS_PROXY= http_proxy= https_proxy= NO_PROXY='*' /tmp/mf-server`。用户自己在终端启动不受影响。

**保留的诊断日志**（有价值，非噪音）：`stream: open remote source failed`（含 song/source_type/path/err）、`stream: local file missing`、`stream: build media source failed`。临时 probe / interceptor / `webdav source config` 日志和 `internal/scanner/tmp_wd_test.go` 已删除。

## FnMusic macOS 桌面端（新增 `:desktop` 模块）

**目标**：用户要 "打包 macOS 制品"，确认选择「让 FnMusic 支持 macOS 桌面端」，于是新建 Kotlin JVM + Compose Multiplatform 1.12.2 的 `:desktop` 模块，不复用 Android 的 designsystem/player（Media3 仅 Android）。

**结构**（`desktop/src/main/kotlin/com/seasonyuu/fnmusic/desktop/`）
- `Main.kt`：`application {}` 窗口（1180×780，最小 940×640），`AppRoot` 在登录/曲库间切换，表单状态提到根部以便登出后保留。
- `AppModel.kt`：状态机（Section/Detail/搜索/队列/播放），`SessionStore` 存 `~/Library/Application Support/FnMusic/session.json`。
- `data/MusicFreeClient.kt`：直接用 OkHttp + kotlinx.serialization 说 REST（不引 Retrofit），映射到 `core:model` 的 Track/Album/Artist/Playlist。
- `play/DesktopAudioPlayer.kt`：`javax.sound.sampled` + mp3spi/JLayer，先整曲缓存到 `~/Library/Caches/FnMusic/audio` 再播，seek 靠重启 worker 跳过帧。
- `ui/`：`Theme.kt`（取自 logo 的暖黑 #131010 + 朱红 #E85C3A + 奶油 #F6EFE3）、`Icons.kt`（24×24 path 数据 + PathParser，避免引 material-icons）、`CoverArt.kt`（OkHttp + Skia 解码 + ConcurrentHashMap 缓存）、`LoginScreen/BrowserScreen/PlayerBar`。

**要点**
- 后端 `/rest/api/v1/songs` 的 JSON 里 `album` 是字符串属性（不是对象），`albumId` 要单独取；`artists` 数组可能含简繁两个同名条目（服务端 tag 如此，不是 bug）。
- 分页：`GridCells.Adaptive(190.dp)`；列表用 `derivedStateOf` 观察可见尾部触发 `loadMore()`。
- `select()` 原来只判 `section == target` 就 return，导致登录/恢复会话后列表永远是空 → 改为「该分区已有数据才短路」。
- 打包：`macOS { iconFile.set(icons/app.icns); minimumSystemVersion = "12.0" }`；icns 由 `/tmp/mf_logo_1024.png` 经 `sips` 生成 iconset + `iconutil` 合成。

**验证手段（无屏幕录制权限时很有用）**
- `ImageComposeScene(width=1180*2, height=780*2, density=Density(2f))` 可离屏渲染整窗口成 PNG → `ScreenshotTest`（`FNMUSIC_SHOTS=1` 才跑）逐页截图，逐张肉眼校对布局。注意宽高是**物理像素**，density=2 时要 ×2，否则只看到左上角。
- `MusicFreeClientTest`：`FNMUSIC_TEST_SERVER=... FNMUSIC_TEST_USER/PASSWORD` 时跑真机后端（登录→列表→专辑→搜索→取流→解码断言）；`FNMUSIC_AUDIO_TEST=1` 额外跑真实播放（位置前进即通过）。Gradle 测试 JVM 不继承 shell 环境，需在 `tasks.test` 里显式 `environment(key, System.getenv(key))`，且要 `./gradlew --stop` 刷新 daemon 环境。
- 制品：`desktop/build/compose/binaries/main/dmg/FnMusic-1.0.0.dmg`，已复制到 `dist/FnMusic-1.0.0.dmg`（72MB，arm64）。

**坑**
- `var query` 会自动生成 `setQuery`，手写 `fun setQuery(...)` 会 JVM 签名冲突 → 方法改名 `updateQuery`。
- `startWorker` 标了 `suspend` 但被非挂起的 `seekTo` 调用 → 去掉 suspend。
- `max(Float, Double)` 会 ambiguous → 显式 `.toDouble()`。
- kotlinx JSON 里 `a?.list(x) ?: b?.list(y)` 类型是 `List?`，`.objects()` 前要 `.orEmpty()`。
- JUnit4 测试方法 `= runBlocking { ... }` 尾部若返回非 Unit 会报 InvalidTestClassError。

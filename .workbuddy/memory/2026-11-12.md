## FNID 连接恢复机制重构（无法连接 → 循环探测 → 请求重放 / 重新登录）

用户反馈：一天前登录的 FNID 会话显示「无法连接」，很长时间不自动恢复，必须手动重新登录。

### 原有探测周期
登录 / 冷启动恢复会话时立即探测一次，之后 `Timer.periodic(2min)` 轮询；请求在传输层失败时经 `onTransportFailure` 立即探测一次（10s 节流）；全部地址离线且是 FNID 时 `_recoverFnConnect()`（5min 节流）刷新 fnOS token 后再探测。

### 根因
1. `pingAddress` 用带认证的 `rest/ping.view`；JWT / subsonicToken 过期返回 401 或 Subsonic code 40/41，一律被判 `online: false` → 所有链路「不可达」，其实服务器活着，只是凭据失效。
2. `_recoverFnConnect()` 只重新登录 fnOS、刷新网关/中继 token，**从不换 Music Free 的 session.token**，所以每 2 分钟探测一次、永远失败；且无 NAS 凭据 / 无 lastFnId / 2FA / 无远程链路时静默 return，UI 无任何提示。
3. 旧 `onTransportFailure` 是 fire-and-forget void 回调，失败请求直接抛错，探测切到新地址后本次请求也不会重放；401 返回合法 JSON 时连探测都不触发。
4. `signedIn` 只看 `session != null`，token 过期不会导向登录页。

### 改动
- `lib/data/models.dart`：`ServerInfo` 增加 `authRequired`。
- `lib/data/musicfree_client.dart`：新增 `TransportException`；`_send` 分类 transport / auth / 业务错误，恢复成功后重放一次请求；`onTransportFailure` / `onAuthFailure` 改为可等待的 `Future<bool> Function()`；`_get` 的 URI 与 headers 在闭包内构造；`_post` 全部 `retryable: false`；`pingAddress` 把 401 / code 40 标为 `authRequired`；`gatewayLogin(anonymous: true)` 供静默重登（不带过期 Bearer）；`_authMessage` 保留后端 401 原文。
- `lib/state/app_model.dart`：探测共享 in-flight（替代 10s 节流）；全离线时 3/5/10/20/30s 退避循环探测，连续 3 轮触发 `reloginRequired`；`_reloginSilently()` 走 `/app/` 网关免密重登；`_recoverFnConnect()` 改返回 bool；网络恢复自动清除重登状态并回到首页。
- `lib/main.dart` + `lib/ui/login_page.dart`：`reloginRequired` 显示登录页 + 提示，FNID 会话自动切到 FNID tab。
- `test/fn_failover_test.dart`：补充请求重放、401 分类、ping authRequired、离线循环→重登→自动恢复、匿名重登、登录 401 文案等回归用例。

### 验证
`flutter analyze` 无问题；`flutter test` 123 项全通过（Windows 绕代理）。未打包任何安装包，用户在 VS Code 热更新验证。

### 边界 / 可调参数
- 退避与阈值在 `app_model.dart` 的 `_offlineBackoff` / `_reloginAfterFailures`（默认 3 轮约 18s）；`_reloginCooldown` 30s、`_reauthCooldown` 5min。
- 封面 / 播放流 URL 不走 `_send`，播放中的流不会随地址切换重连（沿用既有约定）。
- 普通登录未持久化 Music Free 应用密码，无法静默重登，只能回登录页；FNID 且登录时预热过 NAS 账号才能全自动恢复。
- 后端不在本机（macOS 的 `~/Documents/code/music-free/backend`），JWT 具体有效期未核对，「一天过期」是据现象与代码推断。

## FNID 登录端口：去掉表单项，定死 14533

用户先反馈「端口不显示了，永远是 14533」，中间我尝试把端口字段改为常显（方向理解反了，用户已回退该改动），最终明确需求：**FNID 登录页不要端口表单项，端口在代码里定死为 14533**。

实现：
- `lib/data/fn_connect.dart`：新增 `const int kDefaultBackendPort = 14533`；删除 `_lastFnPortKey` / `loadLastFnPort()` / `saveLastFnPort()`（连同 SharedPreferences 持久化），旧设备里残留的 `musicfly.fn.port` 键成为孤儿数据、不再读取。`buildFnCandidates` 仍保留 `backendPort` 位置参数（纯函数、测试用），但登录流程只传常量。
- `lib/state/app_model.dart`：`prepareFnConnect()` 移除 `required String backendPort` 参数，内部 `const port = kDefaultBackendPort`；删掉两处 `saveLastFnPort(port)`。
- `lib/ui/login_page.dart`：删掉 `_port` controller、initState 的端口预填、dispose、`_submit` / `submit()` 的 `backendPort` 传参，以及 `if (needsNas)` 条件下的「服务端口」`MfField`。FNID 第一步现在只需要 FNID（离开内网时再填飞牛账号）。
- 测试：`test/fn_connect_test.dart` 断言 `kDefaultBackendPort == 14533` 且直连候选端口全为 14533；`test/branding_test.dart` 断言 FNID 页签不含「服务端口」字段。

验证：`flutter analyze` 无问题；`flutter test` 130 项全通过（Windows 绕代理）。未打包安装包。

## 登录页提示收敛 + 溢出修复

用户截图反馈：重登时「提示太多，部分提示溢出」。定位到重登场景 `reloginRequired` 不改变内存里的 `_fnProbe`，所以登录页仍显示第二步，于是顶部 notice 状态条 + 第二步「第一步完成」带框卡片 + 长说明句三层叠加；卡片内长文本换行把右侧「重新连接」和下方说明挤到边界外，`Mf.faint`(#6B6259) 在深色底上又太暗，看起来像被截断。

改动（`lib/ui/login_page.dart`）：
- 新增 `_StatusBanner`：全页一次只显示一条状态条，`model.error` 优先于 `widget.notice`；reason 与「网络恢复后自动返回」合并成一行；`Row` + `Expanded` + `maxLines: 2/3` + `overflow: ellipsis`，错误文案最多 3 行。原先表单下方的独立错误框已移除，统一移到 tab 下方。
- `_fnConnectStep2` 去掉带边框的大卡片，改为一行 muted 小字「已连接 · N 条可达链路，M 条备用」+ 右侧「重新连接」；重登/出错时（`widget.notice != null || model.error != null`）隐藏该摘要、只留右对齐的「重新连接」。第二步说明句缩短并加行数上限。
- 第一步说明与「外网自动切换」文案精简，全部加 `maxLines`/`ellipsis`，颜色从 `Mf.faint` 提到 `Mf.muted`。

测试（`test/branding_test.dart`）：新增「重登只显示一条紧凑状态条（旧两行文案消失）」与「320x640 窄屏状态条无布局异常」。`flutter analyze` 无问题、`flutter test` 132 项全通过。未打包。

## 修复：播放时没有总时长、进度条不动

- 根因（两层）：
  1. 客户端 `streamUrl()` 默认对所有歌都带 `format=mp3&maxBitRate=192` 强制转码。转码流是 `200 + Transfer-Encoding: chunked + Accept-Ranges: none`，AVPlayer/ExoPlayer 把它当无限流，`durationStream` 发出 0（darwin `CMTimeGetSeconds` 对不定长流是 NaN → 0）。这个 0 经 `copyWith` 把服务端元数据给的时长**抹掉了** → 总时长 00:00，进度 fraction = 0/0 恒为 0，条不动。
  2. 直传流是 `206 + Content-Length + Accept-Ranges: bytes`，时长、拖动、音质全正常。
- 修复：
  - `Track` 加 `format` 字段，解析 Subsonic `suffix`。
  - `musicfree_client.dart` 新增 `needsTranscode()`：只有 wma/ape/ogg/oga/opus/aifc/ac3/dts/webm 走 mp3 转码，其余直传原始流（顺带解决了 FLAC 全库被压成 192k mp3 的音质问题）。
  - `player.dart` 的 `durationStream` 监听忽略 `<= Duration.zero`，不再让引擎的 0 覆盖元数据时长。
- 实测后端：FLAC 直传 206/audio/flac/22.7MB 完整文件；wma 仍走转码（chunked），此时进度依赖元数据时长（durationStream guard 兜底）。
- 测试 +3（needsTranscode 分类、Track.format），34 全过；DMG/APK 重打包。

## 修复：进度条不动的真正根因（maxBitRate 单独也会触发转码）

- 上轮只把 `format` 置空，但 `streamUrl` 仍带默认 `maxBitRate=192`。实测后端：FLAC 只带 maxBitRate 不带 format 时，响应是 `200 + Transfer-Encoding: chunked + audio/mpeg + Accept-Ranges: none`——**这台 Go 后端仅凭 maxBitRate 就启动转码**，所以直传从未生效，症状原样保留。
- 修复：`_startTrack` 里转码判断同时决定 format 与 maxBitRate（`needsTranscode` → mp3+192，否则两个都 null）；`streamUrl` 默认参数也改为 null，防新调用点踩坑。
- 播放记录（06:0x UTC = 14:0x 本地）显示用户播的「点歌的人」是本地 FLAC，走的仍是 chunked 转码流，与该结论吻合。

## 转码流进度条冻结修复（2026-11-07 晚）

- 现象：《只要平凡》（张杰&张碧晨）能出声但进度条不动。根因：该文件是 WMA（`suffix="wma"`），走 `format=mp3&maxBitRate=192` 实时转码；转码响应 chunked + `Accept-Ranges: none`，AVPlayer 的 positionStream 不前进（即 app_model 注释里描述过的已知问题，wma 强制转码无法像 mp3 那样直传规避）。

- 4 个测试文件 fake play() 签名同步加 `bool transcoded = false`。analyze 0 问题，56 测试全过。

## 「Operation Stopped」无法播放定位（2026-11-07 晚，第二轮服务端修复）

- 现象：《一生中最爱》《一起走过的日子》（均为 阿梨粤 2022《不该用情》FLAC 专辑）报 "Operation Stopped" 被跳过。
- 定位：两首来自 WebDAV 远端源；`serveRawFromSource` 忽略 Range 返回 200 全量流（Accept-Ranges: none）。AVPlayer 先发 `Range: bytes=0-1` 探测，得不到 206 反复重试后放弃 → "Operation Stopped"。文件本身完好（ffprobe 265s 正常）。
- 修复（song_handler.go）：`serveRawFromSource` 支持 HTTP Range——`parseHTTPRange` 支持 bytes=N-/N-M/后缀区间并按 size 收敛；优先 `WebDAVSource.ReadStreamRange`（gowebdav 对 200 响应会自行丢弃 offset+截断，安全），源不支持时顺序丢弃兜底；无 Range 仍 200 全量。播放统计保持原状（Range 去重由 PlayHistoryService 负责，有既有测试 TestSongStream_RangeRepeat_CountsOnce 锁定该语义，勿用 Range 排除计数）。
- 新测试：TestParseHTTPRange、TestServeRawFromSource_RangeSupport（探测 2 字节/中段区间字节一致性/全量 200）。全部 31 包通过，vet 干净。
- 教训：scan3 空查询不返回数据；并发 curl 追加同一文件会交错损坏（errors=ignore 可解析）。
